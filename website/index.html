1.1 Motivation

Readers rarely move through a paper in a straight line. They skim the abstract, jump to a figure, and return to the method when a claim seems too strong. Each jump costs context: the reader has to remember where a statement came from before judging whether it holds.

Assistants that answer without the passage in view make this worse. A fluent summary can blur the line between what the authors claim and what their experiments show. We argue that every explanation should stay attached to the sentence that prompted it.

Translation raises the same problem. A side-by-side view helps only when each translated sentence can be traced to its source, so that a term can be checked against the original wording.

1.2 Contributions

We make three contributions. First, we align source and translated text at the sentence level, so that hovering or selecting on either side marks the same span on the other. Second, we keep a reader's highlights, notes and questions anchored to positions in the original document. Third, we send the selected passage with each question, and link every answer back to it.

1.1 研究动机

读者很少从头到尾按顺序读完一篇论文。他们会略读摘要、跳到某张图，在某个结论显得过强时再回到方法部分。每一次跳转都有上下文成本：判断一句话是否成立之前，读者必须记得它出自哪里。

脱离原文段落作答的助手会让情况更糟。流畅的总结可能模糊作者的主张与实验实际表明的内容之间的界线。我们认为，每一次解释都应当与引出它的那句原文保持关联。

翻译也面临同样的问题。只有当每个译句都能追溯到原句、术语可以与原文措辞核对时，对照阅读才真正有用。

1.2 本文贡献

本文有三点贡献。第一，我们在句子层面对齐原文与译文，在任一侧悬停或选中，另一侧都会标出同一段文字。第二，读者的高亮、批注和问题都锚定在原文中的位置上。第三，每次提问都会附上所选段落，每条回答都能链接回原文。

Local-first

你的书库，
只留在你的电脑上。

原始文件存放在文件系统，论文信息、进度、批注、对话与设置存放在 SQLite。没有内置云同步。

  • 只监听本机回环地址Go 服务绑定 127.0.0.1 的随机端口，每次启动生成新令牌，应用关闭即停止。
  • 文档内容按不可信处理EPUB 导入时检查压缩包大小与资源路径，并在渲染前移除活动内容。
  • 由你决定 AI 看到什么提问时只发送选区、当前章节或页面与近期对话，翻译时发送正文与图题；均经由官方 CLI，在临时空目录中运行。
  • 在线补全只发编号自动补全论文信息只发送识别到的 DOI 或 arXiv 编号，可在设置中关闭。

Get started

三步，开始第一页。

下载安装包，或使用 Node.js 22+、pnpm 10 与 Go 1.26 从源码运行。

安装

macOS（Apple Silicon）下载 DMG，Windows x64 下载 EXE。安装包没有开发者证书，首次打开需允许系统安全提示；之后可在应用内检查更新。

# or from source git clone https://github.com/cynicalight/reader.git cd reader && pnpm install pnpm desktop
2

登录一个 CLI（可选）

阅读、搜索与笔记都不需要 AI。想用 AI 助读时，用官方 CLI 登录即可。

把 PDF 拖入论文库、按 ⌘O，或用 DOI、arXiv 编号导入。超过 50 页的 PDF 会询问是否放入图书库。

FAQ

常见问题

需要填写 API Key 吗？

不需要。Reader 调用你已登录的官方 Claude Code、Codex 或 Kimi CLI；权限、额度、模型与计费都跟随该 CLI 账户。

我的文档会被上传吗？

文档本身留在本机。启用主 Agent 后，导入 PDF 的正文与图题会发送翻译，公式图片会发送转换为 LaTeX，图表和表格不会发送；提问、解释或总结时，选区或当前章节 / 页面以及近期对话会经由 CLI 发送。论文信息补全只发送 DOI 或 arXiv 编号。

论文库和图书库有什么区别？

论文库只收 PDF，单个文件不超过 50 MB、150 页，提供论文信息、分类、标签、引用导出与全文翻译；图书库放 EPUB 与长篇 PDF，按章手动翻译。两库共用阅读界面，启动时进入哪个库可在设置中选择。

支持哪些平台？

提供 macOS（Apple Silicon）与 Windows x64 安装包，均没有开发者证书；Windows 版尚未完成安装后的人工验收。暂不提供 Linux 安装包，可以从源码运行。

扫描版 PDF 可以用吗？

暂未实现 OCR，扫描页会被明确标注为文本不完整。目前主要面向带文本的 PDF 与无 DRM 的流式 EPUB。

第一次打开 PDF 为什么要等一会儿？

首次分析会下载并校验约 67 MB 的版面模型，之后缓存在本地。不需要安装 Python 或 PaddlePaddle，重启后会继续处理。
