# PDF 翻译与对照阅读

## 已确认的交互

- 仅改变中间阅读区域，提供仅原文、原文译文、仅译文。双栏支持交换左右。
- 原文保留 PDF.js 渲染、划词、笔记及高亮。文字 block hover：右上角询问 AI，右下角整段翻译。
- 译文按连续单栏排版，保留标题、段落、图表、公式和阅读顺序。双栏和仅译文共用译文。
- 沉淀阶段翻译全文，逐段开放并本地保存；未完成段落显示状态，失败部分独立重试。
- 仅原文点击段落翻译打开附近的浮层，提供进入双栏入口；未完成段落显示正在翻译中，继续等待全文任务，不单独插队。
- 翻译摘要、标题、正文、图注、表注、脚注和可提取的表格文字。公式、代码、原图和参考文献条目保留。扫描页明确提示 OCR 限制。
- 双向 hover 按 blockId 对应：鼠标停在任一侧段落时，两侧显示同一段落的背景标记；离开、滚动或切换模式清除临时标记。hover 不主动滚动、不改变划词选区或持久标注。
- 双向划词采用句子级对应；跨句对应多个句子。译文划词保留实际选区，原文通过 PDF.js 文字层的完整句子 Range 与 CSS Custom Highlight API 显示浅灰色关联高亮。匹配失败的句子不画近似文本框或整段色块；文字层尚未就绪时等待渲染后重建。仅接触相邻句子边界不算选中该句。原文反向匹配缺少可靠映射时仍退回译文段落。关联高亮临时显示，与持久笔记区分。
- 原文匹配先使用精确文本；数学字母或下标被解析器移到行尾时，允许按完整正文匹配，再保留 PDF 中的实际字符范围。整段正文和数学字母集合一致时，用段落内顺序确定句子；缺少整段对应时，仅接受足够长、唯一且数学字母集合一致的完整句子。段落上下各保留一行查找余量，避免解析边框裁掉末行；该余量不直接参与绘制。
- 译文蓝色选区保留浏览器原生 Range、拖选、键盘扩选和复制行为，通过 Custom Highlight 显示贴合文字的背景，不改变阅读行距。只在自定义背景已生效时隐藏原生整行选区背景；清空选区、离开译文或关闭面板时恢复。不支持该 API 的浏览器保留原生选区。
- 原文译文始终双向同步滚动，不提供关闭开关；滚动按段落和阅读顺序定位，不按全文滚动百分比映射。程序滚动不能触发反向同步。
- 设置中提供独立的「单栏阅读」开关，默认开启，开启后适用于仅原文和原文译文。切换展示模式不改变开关或倍率。
- 首次开启或主动点击「适合单栏」时，双栏页面使用 150%，原生单栏页面按正文宽度撑满当前原文面板。之后换栏、翻页、混排区域切换和面板尺寸变化只移动位置，保持倍率。
- 页眉、页脚、页码在 PDF 中保留，但退出阅读导航、block hover 和翻译。复用 Paddle 已有分类与坐标，不增加模型调用；解析前使用缓存的 PDF.js 文字坐标、边缘页码和相邻页重复边缘文字保守过滤，保留脚注和图注。
- 当前栏末尾滚动到视口中线后，继续向下进入下一栏顶部；栏首向上进入上一栏底部。跨页保持阅读顺序，阻止同一次惯性连续换栏。自动换栏、定位和原文跟随采用短暂平滑移动，手动操作可中断；系统减少动态效果时直接定位。原文滚动条隐藏，保留滚轮与触控板滚动。
- 允许自由缩放和横向移动，此后暂停自动换栏；浮现适合单栏按钮，按当前阅读位置恢复。

## 批量流式翻译

- 按阅读顺序累计 10,000 个原文 Unicode 字符，达到目标后保留整个当前段落，在段尾切分。阈值允许超出，绝不截断段落。
- 默认并发三个 batch；空位释放后继续领取下一批。重试沿用原始批次边界，仅发送尚未完成的段落。
- 每次附带文档标题、作者、首页题名作者区域的原文资料，以及批次前后各两段原文。上下文不计入待译字符数，不额外输出译文。
- Prompt 为每段提供稳定的 blockId、sourceHash 和 source。每行 JSONL 必须原样返回对应 ID 与 hash，并输出按序覆盖原文的 sentences；禁止合并或拆分段落，禁止输出上下文段落。
- 增量片段只缓存尚未收齐的一行。完整行立即解析、校验、落库并发布 SSE 事件，不等 batch 完成。无换行尾行只有在 provider 成功结束且 JSON 完整时接受。
- 未知 ID、错版本、缺句、重复行不能覆盖已完成段落。中断保留已保存结果，重试只补失败或缺失部分。
- GET `/api/documents/{id}/translations/stream` 使用现有会话认证。连接建立时先发 `snapshot`（段落数组），随后每次保存发 `translation`（单段）；每个事件立即 flush。断线重连重新获取快照，不使用定时 GET 轮询。
- 前端按 blockId 更新对应位置，各 batch 的返回顺序不会改变文档顺序。关闭阅读界面只关闭订阅，后台翻译继续。
- 翻译请求上限为每批 20 分钟，其他生成请求仍为原有三分钟；沿用生成器的输出大小限制。超出限制的长段落完整保留为失败待重试，不硬切原文。

## 实现边界

- 原始 PDF、既有笔记及图表解析稿不覆盖。翻译采用按段提交：完整 JSONL 行通过段落 ID、原文版本与句子覆盖校验后立即保存并显示。已保存的段落不依赖整个 provider 请求最终成功；聊天仍保留原有完成后保存规则。
- 翻译内容作为不可信资料，只用于生成内容，不授予执行工具的权限。
- 翻译缓存与原文版本绑定，句子覆盖必须完整且保持顺序；不可靠映射不得伪装为精确对应。
- 分栏需要兼容跨栏标题和图表；低置信度回退到整页。PDF.js 是原文渲染与文字选择的唯一引擎。
- 译文侧标注保留其语言和文字范围，同时关联到原文位置，不能把译文引用误当作原文搜索词。
- 自动跟随尊重手动缩放；主动侧控制同步，模式切换和 resize 尽量保持阅读位置。

## 原文块修复

- 文字坐标统一使用有效的字体 ascent；为零或无效时依次使用有效 descent 和 0.8 的回退值。正文提取和前端句子定位共用这条规则。
- 同一栏中互不重叠的块按上下位置约束排序；跨栏部分保留模型顺序，全宽区域约束两侧。排序不改变现有缓存的 block ID、矩形和图片引用。
- `node apps/processor/dist/repair-text.mjs --input PDF --manifest 原缓存/manifest.json --output 空目录` 可生成修复候选，不重新调用 Paddle，也不覆盖原缓存。输入 PDF 必须匹配原 manifest 的 SHA256。
- 发布候选前停止对应 Reader 实例，备份原 `manifest.json` 和 `paper.md`，核对 ID、矩形和资源引用不变，再替换这两个文件。原笔记、图表解释和历史译文保留。重启后按原文 hash 复用未变化的译文，变化的段落进入现有后台翻译队列；旧译文上的标注不会错误贴到新版本文字。
