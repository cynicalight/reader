# PDF 精读与并行处理

本轮根据 2026-10-04 讨论实施。保持 Electron、React/TypeScript、shadcn/Base UI 与 Go。EPUB 原有阅读能力保留。

## 产品行为

导入后先完成版面学习，再生成译文。学习中：保存原文件、恢复章节和阅读顺序、生成 paper.md、识别并裁切表格/公式/图表，记录分类、页码、归一化区域和附件。图表和表格附件不再调用模型生成解析稿；旧版本已保存的 `transcripts/` 文件保留在磁盘上，但不再读取或更新。处理未完成也允许阅读和问答，显式提示缺少的材料。

图表悬停显示低对比区域提示，点击解释才再次发送原图。结果进入右侧当前话题，带原文引用。整篇提问检索正文和附件解析稿，区分论文证据与背景解释，默认不联网。引用点击跳转并临时高亮，可返回之前位置。

每篇论文允许多个话题。用户主动把回答保存为独立笔记卡片；卡片关联原文，原有批注继续保留。通过对话纠正派生解析稿：AI 提出变更，用户查看本地文本及差异并确认后才保存。原 PDF 不修改。人工确认稿不被自动预处理覆盖。

## 公式片段与附件图题翻译

公式不生成解析稿或独立公式文件。进入翻译阶段后，单独的图片任务与正文翻译并行运行，将原公式截图转换为仅含 `$$` 数学块的 LaTeX Markdown，结果保存在该块的翻译记录 `formulaMarkdown` 中。通过现有译文 SSE 逐块更新，关闭阅读界面不会中止后台任务；重启后未完成任务继续处理，已完成公式不重复调用模型。阅读界面先用原公式图片占位，转换完成后渲染 KaTeX，编号保持在右侧同行。转换失败保留原图并提供“重试公式”，不阻止正文翻译；语法无法渲染时回退原图，可展开原公式核对。不会从旧解析稿提取或迁移公式。

表格、图表、图片及其他有图片附件的块，仅将 `Caption` 送入待译段落和相邻翻译上下文，内部 `Text` 不参与翻译。译文显示原图与译后图题；没有图题时只显示原图。本次不做旧解析稿迁移或格式转换，也不新增正文内行内公式的定位。

开发预览：`pnpm --filter @reader/web dev` 后打开 `/__formula-caption`。这是合成示例，只验证公式片段和原表图加中文图题的展示；不代表真实 PDF 已通过识别。手动检查窄窗口的公式滚动、明暗主题，以及实际新导入文档的原图回退与图题翻译。

## 连接与能力

优先接入系统 PATH 中的 codex、claude、kimi。命令存在、登录状态、实际文字调用和识图验证分别记录；仅实际测试成功显示绿色可用 badge。内置合成文字和图片用于测试，不读取凭据文件，不发送论文作为测试材料。

用户显式指定唯一主 Agent，不自动尝试其他 Agent。备用文字和可选图片 API 配置包含地址、模型和 Key。主 Agent 失败时使用对应的、经过验证的 API，并明确提示切换；取消不触发 fallback。图像调用只能使用通过识图验证的配置。

## 工程约束

后台任务按文档持久化，串行版面处理。版面索引发布后启动正文／Caption／公式翻译，保存状态、进度、失败和等待配置状态。退出时取消并等待子任务，重启仅恢复未完成的任务，已完成的译文和公式不重复调用模型。旧版本保存的沉淀状态在启动时移除，仅按翻译状态汇总。封面学习阶段展示单条进度，随后在封面底部单行展示翻译状态及完成数量；等待配置或失败时可点击状态进行配置或重试；运行状态使用轻微呼吸圆点，完成数量变化时轻微淡入，完成时勾选淡入；翻译完成后面板淡出。系统开启减少动态效果时禁用这些动画。模型固定版本及 SHA256 校验，首次缓存后离线推理。PDF.js 用于本机页面渲染与文本提取，ONNX 用于版面定位。不得将仅靠文件扩展名、命令存在、模型自述能力当作验证结果。

派生文件仅通过 document/block ID 访问。修订使用版本校验和明确应用操作，不允许模型提供任意路径或直接写文件。文档文本和模型回答均视为不可信数据。API Key 仅存后端受限权限文件，响应不回传密钥。客户端只获得是否已配置的状态。

## 验证

覆盖任务恢复、附件失败重试、部分完成问答、会话隔离、引用来源、修订冲突、取消与 fallback、真实 CLI 图像协议、模型真实推理。原生桌面视觉验收按项目规则由用户完成，不使用浏览器自动化。
