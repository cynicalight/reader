# PDF 精读与双阶段处理

本轮根据 2026-10-04 讨论实施。保持 Electron、React/TypeScript、shadcn/Base UI 与 Go。EPUB 原有阅读能力保留。

## 产品行为

导入后立即开始两阶段处理。学习中：保存原文件、恢复章节和阅读顺序、生成 paper.md、识别并裁切表格/公式/图表，记录分类、页码、归一化区域和附件。沉淀中：异步调用经过识图验证的主 Agent，把各附件转为可检索的文字稿。附件逐个保存并复用；失败可重试，不能伪装为完成。无图像附件直接完成。处理未完成也允许阅读和问答，显式提示缺少的材料。

图表悬停显示低对比区域提示，点击解释才再次发送原图。结果进入右侧当前话题，带原文引用。整篇提问检索正文和附件解析稿，区分论文证据与背景解释，默认不联网。引用点击跳转并临时高亮，可返回之前位置。

每篇论文允许多个话题。用户主动把回答保存为独立笔记卡片；卡片关联原文，原有批注继续保留。通过对话纠正派生解析稿：AI 提出变更，用户查看本地文本及差异并确认后才保存。原 PDF 不修改。人工确认稿不被自动预处理覆盖。

## 公式片段与附件图题翻译

新处理的公式附件使用专用沉淀提示，输出独立成行的 `$$` LaTeX 数学块及块外解释。完整结果仍保存为 `transcripts/<块 ID>.md`，另将数学块单独保存为 `formulas/<块 ID>.md`。公式片段保存成功后才进入正文翻译；缺少数学块视为失败，可重试，不把解释当成公式。文档块接口返回 `formulaMarkdown`，译文按块的原有顺序插入公式片段，使用 KaTeX 渲染；无法渲染时保留原图，可展开原公式核对。公式不再次发送给文字翻译模型。

表格、图表、图片及其他有图片附件的块，仅将 `Caption` 送入待译段落和相邻翻译上下文，内部 `Text` 不参与翻译。译文显示原图与译后图题；没有图题时只显示原图。表格沉淀稿不直接进入译文。本次不做旧解析稿迁移或格式转换，也不新增行内公式 OCR 和公式编号合并。

开发预览：`pnpm --filter @reader/web dev` 后打开 `/__formula-caption`。这是合成示例，只验证公式片段和原表图加中文图题的展示；不代表真实 PDF 已通过识别。手动检查窄窗口的公式滚动、明暗主题，以及实际新导入文档的原图回退与图题翻译。

## 连接与能力

优先接入系统 PATH 中的 codex、claude、kimi。命令存在、登录状态、实际文字调用和识图验证分别记录；仅实际测试成功显示绿色可用 badge。内置合成文字和图片用于测试，不读取凭据文件，不发送论文作为测试材料。

用户显式指定唯一主 Agent，不自动尝试其他 Agent。备用文字和可选图片 API 配置包含地址、模型和 Key。主 Agent 失败时使用对应的、经过验证的 API，并明确提示切换；取消不触发 fallback。图像调用只能使用通过识图验证的配置。

## 工程约束

后台任务按文档持久化，串行版面处理，附件结果逐个提交；退出中断后可恢复。模型固定版本及 SHA256 校验，首次缓存后离线推理。PDF.js 用于本机页面渲染与文本提取，ONNX 用于版面定位。不得将仅靠文件扩展名、命令存在、模型自述能力当作验证结果。

派生文件仅通过 document/block ID 访问。修订使用版本校验和明确应用操作，不允许模型提供任意路径或直接写文件。文档文本和模型回答均视为不可信数据。API Key 仅存后端受限权限文件，响应不回传密钥。客户端只获得是否已配置的状态。

## 验证

覆盖任务恢复、附件失败重试、部分完成问答、会话隔离、引用来源、修订冲突、取消与 fallback、真实 CLI 图像协议、模型真实推理。原生桌面视觉验收按项目规则由用户完成，不使用浏览器自动化。
